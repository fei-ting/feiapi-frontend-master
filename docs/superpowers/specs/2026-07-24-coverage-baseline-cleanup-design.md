# 覆盖率统计范围与质量基线清理设计

## 背景

项目已从 React + Umi 迁移到 Vue 3 + Vite，但本地仍保留被 `.gitignore` 忽略的 `src/.umi` 和 `src/.umi-production` 生成目录。当前项目没有 Umi 依赖，源码、构建脚本和 TypeScript 配置也没有引用这些目录，因此它们属于迁移后的本地遗留产物。当前 Vitest 覆盖率配置使用 `src/**/*.{ts,vue}` 收集运行时代码，导致部分 Umi 生成文件解析失败后被覆盖率工具排除，另一些生成文件以 0% 计入统计。

现有覆盖率命令虽然返回成功，但总体数据混入非业务生成代码，且全局门禁仍停留在语句 59%、分支 52%、函数 56%、行 60%，无法准确反映当前有效业务源码的质量基线。

## 整改目标

- 删除两个遗留 Umi 生成目录，彻底清理已退出项目技术栈的本地产物。
- 删除 `.gitignore` 中的 Umi 目录规则，避免未来意外生成的遗留目录继续被静默隐藏。
- 消除覆盖率执行过程中的 Umi 文件解析警告。
- 根据清理后的实际结果重新固化全局覆盖率门禁，防止整体覆盖率回退。
- 保持现有核心模块独立门禁不变。

## 非本次范围

- 不新增端到端测试框架或业务测试。
- 不调整具体业务模块的测试实现。
- 不修改 ESLint 或持续集成配置；相关问题在 11.3 单独整改。

## 方案比较

### 方案一：删除遗留目录并移除忽略规则

删除本地 `src/.umi` 和 `src/.umi-production`，从 `.gitignore` 删除 `.umi`、`.umi-production`、`.umi-test`，并以清理后的有效结果向下取整设置全局门禁。

优点是彻底清理已经退出技术栈的产物，不在现代覆盖率配置中长期保留 Umi 兼容规则；如果相关目录未来再次出现，Git 会立即显示未跟踪文件，便于发现异常。该方案适合当前个人独立开发项目，不需要兼容其他开发者工作区中的遗留目录。

### 方案二：保留目录并增加精确排除规则

在覆盖率配置中增加 `src/.umi/**` 和 `src/.umi-production/**` 排除规则。该方案可以兼容其他工作区中的遗留目录，但会在 Vue 3 + Vite 项目中长期保留已经退出技术栈的 Umi 兼容配置。

### 方案三：只删除当前本地目录

只删除当前两个本地目录，保留 `.gitignore` 中的 Umi 规则。该方案可以让本次覆盖率恢复正常，但未来相关目录再次出现时仍会被静默隐藏，无法确认迁移遗留是否重新进入工作区。

## 采用方案

采用方案一。

临时使用完整排除参数模拟删除目录后的覆盖率结果，46 个测试文件、259 个测试全部通过，未出现 Umi 解析警告，得到以下有效结果：

| 指标 | 实测结果 | 新全局门禁 |
| --- | ---: | ---: |
| 语句 | 79.35% | 79% |
| 分支 | 74.95% | 74% |
| 函数 | 74.81% | 74% |
| 行 | 79.85% | 79% |

全局门禁按实测结果向下取整，保留不足一个百分点的自然波动空间。现有核心模块门禁继续保持语句和行 90%、函数 85%、分支 80%。

## 清理与配置设计

本次执行以下调整：

1. 删除未被 Git 跟踪的本地 `src/.umi` 目录。
2. 删除未被 Git 跟踪的本地 `src/.umi-production` 目录。
3. 从 `.gitignore` 删除 `.umi`、`.umi-production`、`.umi-test` 三项遗留规则。
4. 在 `vite.config.ts` 中将全局门禁调整为语句 79%、分支 74%、函数 74%、行 79%。
5. 不向 `coverage.exclude` 增加 Umi 专用规则。
6. 不改变覆盖率提供器、报告格式、核心模块路径门禁和测试环境。

删除目录后，覆盖率继续按现有 `src/**/*.{ts,vue}` 规则收集源码。如果 Umi 目录未来意外再次出现，它们会同时被 Git 状态和覆盖率执行暴露，而不会被忽略规则或专用排除规则静默隐藏。

## 验证标准

依次执行以下验证：

1. 文件系统检查：`src/.umi` 和 `src/.umi-production` 均不存在。
2. Git 忽略规则检查：`.gitignore` 不再包含 `.umi`、`.umi-production`、`.umi-test`。
3. `yarn coverage`：46 个测试文件和 259 个测试全部通过，执行过程不再出现 Umi 解析警告，所有门禁通过。
4. `yarn typecheck`：TypeScript 类型检查通过。
5. `yarn build`：生产构建通过。

覆盖率结果应不低于语句 79%、分支 74%、函数 74%、行 79%。如果结果低于门禁，应先查明测试或统计范围差异，不通过降低阈值绕过失败。

## 风险与控制

- 风险：误删仍在使用的源码。控制方式是删除前确认目录未被 Git 跟踪、项目没有 Umi 依赖且源码和配置均无引用；当前三项检查均已通过。
- 风险：Umi 目录未来再次出现。控制方式是删除对应 `.gitignore` 规则，使 Git 状态和覆盖率执行能够立即暴露异常。
- 风险：提高全局门禁后暴露环境差异。控制方式是在本地完成覆盖率、类型检查和构建，并在合并后由 Node.js 22 的 CI 再次验证。
- 风险：误改核心模块门禁。控制方式是仅调整全局四项数值，保持 `coreCoverageThresholds` 及其路径映射不变。

## 预计修改文件

- `vite.config.ts`

`src/.umi` 和 `src/.umi-production` 为未跟踪的本地生成目录，删除操作不会形成 Git 文件变更。
