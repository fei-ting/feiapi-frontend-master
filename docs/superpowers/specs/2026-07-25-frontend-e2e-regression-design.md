# 前端关键业务端到端测试与配额回归修复设计

## 背景

前端已经建立 Vitest 单元测试、组件测试和覆盖率门禁，但认证、路由权限、后台接口管理和配额更新仍缺少真实浏览器中的完整用户链路验证。现有测试可以证明局部函数和组件行为，却不能证明页面、路由、Pinia 状态、HTTP 客户端和浏览器 Cookie 组合后仍然正确。

设计阶段还确认 `src/views/admin/QuotaConfigView.vue` 的保存操作仍是占位实现，只显示提示而不调用更新接口。`git blame` 显示该占位逻辑由 2026-07-15 的 `b18e49d feat: 添加统一应用壳层和布局组件` 引入；拆分前的 `AdminView.vue` 已具有正整数校验、确认操作、更新请求、成功或失败提示以及刷新数据等完整语义。后续单元测试按照占位行为编写，导致回归被固化而没有被发现。

后端已经具有独立集成测试，因此本次前端端到端测试不重复启动数据库、Redis、Nacos 或真实后端服务，而是使用真实 Chromium 和受控 HTTP Mock 验证前端用户链路与公开请求契约。

## 目标

- 引入 Playwright Test，建立可在本地和 CI 稳定运行的前端端到端测试基础设施。
- 覆盖认证与路由权限、接口管理核心操作和配额更新三组关键用户链路。
- 先用失败测试复现配额保存回归，再在现有组件边界内恢复正确业务行为。
- 将端到端测试纳入前端 CI，并保留失败截图、视频、Trace 和 HTML 报告。
- 保持测试与生产业务逻辑隔离，确保测试能够真实发现功能回归。

## 非本次范围

- 不启动或验证真实后端、数据库、Redis、Nacos 和网关。
- 不重复后端已有的 Service、Mapper 或接口集成测试。
- 不覆盖注册、退出、分页筛选和全部异常页面流程；这些作为后续增量场景。
- 不通过测试专用分支、测试后门或内部状态注入改变生产代码行为。
- 不为了提高覆盖率增加没有业务价值的测试。

## 测试真实性原则

### 预期来源

测试预期按以下顺序确定：

1. 已确认的业务需求和验收条件。
2. 后端接口文档、公共请求与响应类型等公开契约。
3. 页面向用户承诺的交互结果。
4. 当前实现只用于定位操作入口，不用于反推正确结果。

不得把当前错误实现固化为测试预期。例如配额保存的正确结果是“校验、确认、提交、刷新并展示新额度”，不能因为当前代码只显示提示，就把提示出现视为保存成功。

### 黑盒边界

- E2E 不直接导入 Vue 组件、Pinia Store、Service 或内部函数。
- E2E 不使用 `page.evaluate()` 修改应用内部状态。
- E2E 从浏览器外部操作页面，只观察可见结果、地址栏、Cookie 和公开 HTTP 请求。
- API Mock 只替代后端系统，不替代前端内部模块。
- Mock 数据按照公开接口契约构造，不复制前端组件或 Service 的实现逻辑。
- 页面定位优先使用角色、标签、标题和可见文本，不依赖 CSS 类名。
- 不增加纯测试用途的生产代码、环境开关或业务分支。

### 有效性证明

配额回归采用红灯、绿灯、重构顺序：

1. 先编写符合业务要求的单元测试和 E2E。
2. 在当前占位实现上执行，确认测试因没有更新请求和数据刷新而失败。
3. 完成最小业务修复，使测试通过。
4. 重构并复跑全部测试。
5. 审查测试，确认移除核心更新调用后测试仍会失败，不通过弱化断言迎合实现。

## 技术方案比较

### 方案一：Playwright Test、Vite 与 HTTP Mock

使用 Playwright Test 启动真实 Chromium，通过 Vite 提供前端页面，并在浏览器网络边界拦截 `/api/**`。该方案支持稳定的网络契约检查、路由验证、截图、视频、Trace、重试和 CI 报告。

### 方案二：Cypress、Vite 与 HTTP Mock

Cypress 的交互式调试成熟，但依赖和运行器更重。项目当前没有 Cypress 生态，引入后不能复用现有能力，也没有相对 Playwright 的明显收益。

### 方案三：Vitest Browser Mode

该方案可以复用 Vitest，但更适合浏览器组件测试。对于跨页面路由、完整登录、Cookie、网络拦截和 CI 失败产物，成熟度和能力不如 Playwright。

## 采用方案

采用方案一。新增 `@playwright/test@1.62.0`，其 Node.js 要求为 `>=20`，兼容本地 Node.js 20.20.2 和 CI Node.js 22，许可证为 Apache-2.0。

Playwright 自动启动固定地址 `http://127.0.0.1:8000` 的 Vite。CI 禁止复用已有服务，防止测试连接到错误进程；本地允许复用开发者已经启动的同地址服务。

## 测试架构

```text
playwright.config.ts
tests/
  e2e/
    fixtures/
      apiMock.ts
      testData.ts
    auth.spec.ts
    interface-management.spec.ts
    quota-config.spec.ts
```

### Playwright 配置

- 首批只运行 Chromium，避免在基础设施建立阶段扩大浏览器矩阵。
- 使用 `http://127.0.0.1:8000` 作为基础地址。
- 使用 Vite `webServer`，端口被占用时直接失败。
- 本地测试允许并行；CI 使用单工作进程和最多两次重试。
- 首次失败时保留 Trace，最终失败时保留截图和视频。
- 生成 HTML 报告和机器可读测试结果。

### API Mock

`apiMock.ts` 为每个测试创建独立的浏览器外部状态：

- 会话状态：匿名用户、普通用户或管理员。
- 接口列表：支持新增、上线、下线和删除。
- 配额列表：支持更新有限额度。
- 请求记录：保存方法、路径、查询参数、请求头和请求体。
- 未处理请求：返回 HTTP 501，并在测试结束时使测试失败。

Mock 不要求前端按照固定请求顺序执行，只校验业务上必要的方法、路径、鉴权边界和请求字段，避免把实现细节写成测试约束。

### 测试数据

`testData.ts` 集中定义虚构的管理员、普通用户、接口和配额数据。每个测试复制独立数据，禁止共享可变状态。数据不包含真实账号、密码、Cookie、API 密钥或其他敏感信息。

## 会话与 CSRF 数据流

管理员登录流程按浏览器真实边界执行：

```text
打开登录页
  -> GET /api/user/get/login 返回匿名状态
  -> 用户填写并提交登录表单
  -> GET /api/csrf 返回 XSRF-TOKEN Cookie
  -> POST /api/user/login 必须携带 X-XSRF-TOKEN
  -> Mock 切换为管理员会话
  -> GET /api/user/get/login 返回管理员
  -> Pinia 刷新状态
  -> 路由进入 /admin/dashboard
```

预置普通用户或管理员的场景由 Playwright 浏览器上下文写入虚构会话 Cookie，同时配置相应 Mock 会话状态。测试不直接修改 Pinia 或应用内部变量。

所有业务成功响应使用真实包装契约：

```json
{
  "code": 0,
  "data": {},
  "message": "ok"
}
```

业务失败同样通过公开错误码和消息返回，由前端 HTTP 客户端正常解包和处理。

## 首批端到端场景

### 认证与权限

- 匿名用户访问 `/profile/info`，跳转到带原目标地址的登录页。
- 普通用户访问 `/admin/dashboard`，被重定向到首页。
- 管理员在登录页提交账号密码，完成 CSRF 初始化、登录、会话刷新并进入后台工作台。

### 接口管理

- 管理员打开新增接口弹窗，填写公开业务字段并提交。
- 测试校验新增请求的关键契约字段和创建后的文档维护路由。
- 对预置的下线接口依次执行发布、下线和确认删除。
- Mock 按公开业务规则更新接口状态，页面每次重新加载列表后展示最新结果。

新增后跳转到文档维护页时，Mock 只补充该目标页正常加载所必需的接口详情和文档详情响应，不扩大本次断言范围。

### 配额更新

- 管理员打开配额页面并加载配额列表。
- 修改有限额度，打开确认弹窗并确认。
- 测试校验更新请求的配额类型和新额度。
- Mock 更新配额状态，页面刷新后显示新额度和成功提示。
- 无限额度类型不提供可编辑输入框。

E2E 只覆盖配额成功主链路。输入边界、取消、请求失败和重复提交由组件单元测试覆盖。

## 配额回归修复设计

在 `QuotaConfigView.vue` 中使用现有 `ConfirmDialog` 恢复以下行为：

1. 保存前将输入转换为数字，并校验为大于 0 的整数。
2. 校验失败时显示错误提示，不打开确认弹窗、不发送请求。
3. 确认弹窗展示配额类型和即将保存的新额度。
4. 确认后调用 `interfaceQuotaConfigService.update()`。
5. 保存期间禁用当前配额的保存按钮和确认操作，防止重复提交。
6. 成功后关闭弹窗、清理确认状态、显示成功提示并重新加载配额列表。
7. 失败时保留弹窗和输入值，显示失败提示，允许用户重试或取消。
8. 为有限额度输入框提供包含配额类型的无障碍名称，使真实用户和自动化工具都能明确识别字段。

恢复逻辑保留在当前页面组件和 Service 边界内，不恢复旧 `AdminView.vue`，也不引入测试专用业务分支。

## 单元测试设计

修改 `src/views/admin/__tests__/QuotaConfigView.test.ts`，删除“点击保存只发出占位提示”的错误预期，新增以下行为测试：

- 非正整数和非整数额度被拒绝。
- 有效额度打开确认弹窗，但确认前不发送更新请求。
- 取消确认不发送请求并保留页面数据。
- 确认后发送正确请求，成功时关闭弹窗、提示成功并刷新数据。
- 请求失败时提示失败、保留确认状态并恢复可操作状态。
- 保存期间不能重复提交。
- 无限额度类型不可编辑。

测试 Mock Service 边界，不 Mock `QuotaConfigView` 自身的核心方法；断言业务结果、状态变化和外部请求。

## 脚本与 CI

新增脚本：

- `yarn e2e`：无界面运行全部 Playwright E2E。
- `yarn e2e:report`：打开最近一次 HTML 报告。

现有 CI 在单元测试、生产构建和构建体积门禁通过后执行：

```text
安装 Chromium 和系统依赖
  -> 运行 Playwright E2E
  -> 始终上传 HTML 报告和失败产物
```

报告和失败产物保留 7 天。Playwright 浏览器只访问本地 Vite 和被拦截的同源 `/api/**`，测试不访问真实业务服务或外部网络。

## 验收标准

- 配额回归测试先在占位实现上因没有更新请求和数据刷新而失败。
- 完成最小修复后，配额组件全部单元测试通过。
- 认证权限、接口管理和配额更新三组 E2E 全部通过。
- E2E 没有未处理的 `/api/**` 请求，也没有直接修改应用内部状态。
- 现有单元测试和组件测试不得回退。
- `yarn coverage`、`yarn typecheck`、`yarn build`、`yarn check:size` 和 `yarn e2e` 全部通过。
- 覆盖率不得通过降低阈值绕过失败。
- 代码审查确认删除配额核心更新调用会导致测试失败。
- CI 配置可以解析，报告和失败产物路径正确。
